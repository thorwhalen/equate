equate.service¶

The service layer: equate’s matching core as JSON-in/JSON-out operations.

This module is the surface-free half of the HTTP service (doc 10 §5, decision D10). Every operation is a plain method taking JSON-able arguments and returning a dataclass of JSON-able fields, so any surface can project it: mk_app() mounts it as an HTTP API with qh (pip install 'equate[service]'), and the review UI in ui/ consumes the same payloads through Zod schemas generated from json_schemas().

Two kinds of operation:

  • stateless — MatchService.match(): two collections in, scored pairs out (the batch core, cached by content);

  • session-scoped — the interactive loop of doc 08. MatchService.open_session() scores the two collections once and keeps a CandidateStore of top-k candidates; candidates() reads (or refreshes) one item’s top-k; edit() applies confirm / reject / reassign edits and returns the locally re-optimized assignment (one constrained LAP over the cached scores, never a re-score); label() is the active-learning Oracle endpoint: it records a human/LLM/crowd label and returns the next most-informative query.

Every response carries an Accounting of the time and item counts each tier (score, match, reoptimize, …) cost, so a caller can budget expensive cascades (doc 06). Sessions live in any MutableMapping (sessions=), so a persistent dol store replaces the in-memory dict without touching this code.

>>> svc = MatchService()
>>> result = svc.match(['apple pie', 'banana split'], ['banana splitt', 'aple pie'])
>>> [(p.left, p.right) for p in result.pairs]
[('apple pie', 'aple pie'), ('banana split', 'banana splitt')]

class equate.service.Edit(action, item, candidate, source='human')[source]¶

Bases: object

One user edit of the assignment.

  • confirm — force item -> candidate (a confirmed match);

  • reject — forbid item -> candidate;

  • reassign — confirm a different candidate for item (its previous forced match, and any other item forced onto candidate, are released);

  • clear — drop any constraint on item -> candidate (undo).

item indexes the left collection, candidate the right one; source says who made the edit ('human', 'llm', …) — provenance for a later precedence policy.

class equate.service.MatchService(*, sessions=None, cache='default', mk_id=<function MatchService.<lambda>>, field_compare='ratio', on_cost=None)[source]¶

Bases: object

equate’s matching core as stateless + session-scoped JSON-able operations.

Every seam is a keyword argument with a working default:

  • sessions — where sessions live (any MutableMapping; default an in-memory dict; pass a pickle-valued dol store to persist them);

  • cache — where stateless match results are cached (default a bounded LRU; pass None to disable);

  • mk_id — session-id factory (default uuid4().hex);

  • field_compare — the per-field comparator used in explanations;

  • on_cost — (tier, seconds, items) hook called on every accounted tier.

edit(session_id, edits)[source]¶

Apply edits (Edit or dicts) and re-optimize the assignment.

Atomic: if an edit is invalid or the edits leave no feasible assignment, a ValueError is raised and the session is unchanged. One constrained LAP over the cached scores — an edit is a cheap re-solve, never a re-score. Concurrent edits of one session (in this process) are serialized, so none is lost.

Return type:

EditResult

match(A, B, *, featurize=None, compare=None, block=None, how='assign', threshold=None, sense=None)[source]¶

Match two collections (stateless). Mirrors equate.match().

how is 'assign' (optimal 1:1), 'greedy', 'stable', 'soft' or 'cluster' (then groups lists the entity clusters over the pooled A + B indices, B offset by len(A)). Pairs below threshold (above it, for a 'minimize' sense) are dropped. Results are cached by content.

Return type:

MatchResult

next_query(session_id)[source]¶

The next pair to label: uncertainty sampling over the not-yet-decided items.

An item is decided once it is confirmed. The pair offered is the item’s current match when it has one, else its best candidate that is neither rejected for it nor confirmed for another item — so labelling never steals a confirmed match back and forth. An item with no such candidate left is skipped.

Return type:

Optional[Query]

open_session(A, B, *, k=5, featurize=None, compare=None, block=None, sense=None, floor=None)[source]¶

Score A against B once and open an interactive review session.

The session keeps each item’s top-k candidates and the optimal 1:1 assignment; every later edit re-solves from these cached scores.

floor is the lowest acceptable score (the highest acceptable distance for a 'minimize' sense). Pairs past it are not candidates at all: never proposed, never offered for review, and a reject never pushes an item onto one — the item is left unmatched. Like blocking (D11), the assignment is then lexicographic: as many acceptable pairs as possible, then the best total score — so a floor can change the opening assignment, not just trim it. That is unlike match()’s threshold, which solves first and then drops weak pairs.

Return type:

SessionView

review(session_id, *, n=None, include_confirmed=True)[source]¶

The review queue: items ordered most-uncertain first (smallest margin).

Confirmed items come last (a human already decided them); include_confirmed= False drops them. Each ReviewItem carries its top-k candidates with field-diff explanations — everything a review row needs.

equate.service.explain_pair(left, right, score, *, field_compare='ratio')[source]¶

A structured Explanation of a pair: a per-field diff.

Records (mappings) are compared field by field over the union of their keys; any other object is one field named value. A side that is absent, None or '' has no similarity (None): missing is not the same as different. details['fields'] is a list of FieldDiff dicts — the payload a UI renders as a side-by-side diff.

>>> e = explain_pair({'name': 'Jon'}, {'name': 'Jon', 'city': 'Paris'}, 0.8)
>>> [(f['field'], f['similarity']) for f in e.details['fields']]
[('name', 1.0), ('city', None)]

equate.service.mk_app(service=None, *, cors_origins=('http://localhost:5173', 'http://127.0.0.1:5173'))[source]¶

Mount a MatchService as an HTTP API (FastAPI, built with qh).

Routes (JSON in, JSON out):

POST   /match                                       stateless match
POST   /sessions                                    open a review session
GET    /sessions/{session_id}                       session state + review queue
DELETE /sessions/{session_id}                       close it
GET    /sessions/{session_id}/candidates/{item}     an item's top-k
POST   /sessions/{session_id}/candidates/{item}     refresh it with {"k": ...}
POST   /sessions/{session_id}/edits                 {"edits": [...]} -> re-optimized
POST   /sessions/{session_id}/label                 oracle label -> next query
GET    /sessions/{session_id}/next                  the next query to label

An unknown session is a 404; an invalid or infeasible edit a 422. cors_origins lets the review UI’s dev server (vite, port 5173) call it; pass () to disable. Requires pip install 'equate[service]'.
